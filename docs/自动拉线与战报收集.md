# 自动拉线与战报收集（Auto Line + Report Collect）

> 功能命名：**自动拉线与战报收集**。
> 在「自动拉线」的空闲时间里自动执行「战报自动收录」，两条流程共用同一台模拟器、
> 同一套 adb 触控，但**不会互相打断**。
>
> 硬约束：**距上一次提交成功（upload ok / 无新增）≥ 10 分钟必须收集**，防止战报积压丢失；
> 上传失败的 capture 会进补交队列，后续空闲点自动补交。

## 1. 为什么绑在一起

- 「自动拉线」每轮有大量**纯等待**：出征后要等部队到达、打完、返回
  （`battle.py::_wait_battle_return`，单次可达 `--battle-timeout` 900s）；
  轮与轮之间还有 `--gap`。
- 「战报自动收录」只需要**几十秒到两三分钟**的独占 UI：进「战报 → 同盟 → 交战」、
  逐卡展开滑到底、pcap 提 BLOB、增量上传、回到地图。
- 把收录塞进空闲时间，既不耽误拉线推进，又能保证「距上次提交」不超过 10 分钟（含失败补交）。

## 2. 触发点与 10 分钟保证

| 触发点 | 时机 | 说明 |
| --- | --- | --- |
| `wait(seconds)` | 等战斗结束的预判等待、轮间隔 | 分片等待，只睡到下一次该收集的时刻，到点立刻插一轮 |
| `safe_point("本轮开始")` | 每轮 `ensure_map()` 之后 | 世界地图 |
| `safe_point("邮件读完")` | `MailReader.back()` 回到地图之后 | 世界地图 |
| `safe_point("调动结束")` | 调动面板 `mob.close()` 之后 | 世界地图 |
| `safe_point("战斗结束")` | 战斗子流程返回（城内视角） | 收集前会 `ensure_map()` 自动「出城」 |
| `safe_point("回家补兵结束")` | `HomeReplenish` 出城回地图之后 | 世界地图 |

调度规则（[`sanmou_auto/report_collector.py`](../report_collector.py)）：

1. **提交硬约束**：距「上一次提交成功」（`uploadOk=true` 或「无新增」）≥
   `--report-submit-interval`（默认 600s）且距上次开始 ≥60s → **必须收集**；
2. **空闲点频次**：距「上一次收集结束」≥ `--report-interval`（默认 300s）才在
   安全点/等待分片里插一轮，避免刚收完又立刻开下一轮，把打架时间挤没；
3. **上传失败不丢**：`captureId` 进 `pendingUploads` 队列（上限 50），
   在 `wait()` / `safe_point()` / 下一次采集前用 `scripts/upload.py --capture-id`
   补交（幂等，服务器按 BLOB 去重）；成功后刷新提交时间并出队；调度基准取
   `max(lastSubmit, lastAttempt)`，上传故障时不会每 60s 风暴式重采；
4. 上次开始/结束/提交/尝试时间与补交队列写入
   `screenshots/flow/report_collect_state.json`，**跨进程重启也继续遵守**（30 天有效）。

## 3. 单次收集做什么

```text
python scripts/round.py --max-seconds <N> --no-wait   # 采集 → 提取 → 增量上传（不等 /api/live）
python scripts/screen.py back-to-map                  # 无论成败都恢复到世界地图
```

- `--no-wait`：不在收集流程里等服务器 `/api/live` 可见（那一步最长可等 900s，
  会吃掉拉线时间）；上传回执里的 `ingestVersion` 仍会记录在明细里。
- `--report-skip-upload`：只采集/提取，不上传（用于现场排障）。
- 若 `control/server_upload.json` 与 `config.json（server.baseUrl 非空）` 都不存在，
  会自动降级为「只采集到本地」，打印一次提示，避免每轮都因上传失败计数。
- 收集期间自动拉线**同步暂停**，不存在触控并发；结束后自动拉线从安全点继续。

## 4. 输出

| 文件 | 内容 |
| --- | --- |
| `screenshots/flow/auto_line_<时间戳>.json` | 自动拉线汇总，新增 `report_collect` 段（次数/失败/最大间隔/超上限次数/状态文件） |
| `screenshots/flow/auto_line_<时间戳>.jsonl` | 逐轮明细，每轮新增 `report_collect`（本轮触发的收集事件） |
| `screenshots/flow/report_collect_state.json` | 上次开始/结束/提交/尝试时间、累计次数、待补交队列、最近 captureId / 错误 |
| `screenshots/flow/report_collect_<时间戳>.jsonl` | 每次收集一条：触发点、间隔、页数、BLOB、记录数、上传、耗时、错误 |

控制台每轮会多一行：

```text
[第 3 轮 08:12:10] 用时 14m02s | 完成 reason=-
    ...
    战报: 收集 2 次（成功 2） | 最近 mumu_adb_production_20261121_081512_301 | 页 4 / BLOB 11 / 记录 63
```

汇总末尾新增：

```text
-- 战报收集 --
  次数 5（失败 0）  空闲间隔 300s / 提交硬约束 600s  实际最大间隔 5m03s  超时 0 次  待补交 0
  最近一次 2026-11-21T08:52:10  captureId=mumu_adb_production_...  ok=True
```

## 5. 用法

```bash
# 默认：自动拉线跑 1 小时；空闲点每 5 分钟收一次，距上次提交 10 分钟必收
python -m sanmou_auto.flow_line_report

# 跑 10 分钟 / 冒烟一轮
python -m sanmou_auto.flow_line_report --minutes 10
python -m sanmou_auto.flow_line_report --max-rounds 1

# 收紧空闲间隔（下限 60s）
python -m sanmou_auto.flow_line_report --report-interval 180

# 调整提交硬约束（距上次提交超过该秒数必收，默认 600）
python -m sanmou_auto.flow_line_report --report-submit-interval 600

# 只抓不上传（排查解码/抓包）
python -m sanmou_auto.flow_line_report --report-skip-upload

# 关闭收集：等价于自动拉线
python -m sanmou_auto.flow_line_report --no-report

# 启动时不立刻收（等满一个间隔）
python -m sanmou_auto.flow_line_report --no-report-first
```

自动拉线参数与 `python -m sanmou_auto.flow_loop` 完全一致（`--troops` / `--no-battle` /
`--no-wait` / `--battle-timeout` / `--no-home` / `--no-city-rest` 等）。

> ⚠️ `--no-wait` 会显著减少可用的等待时间，收集只能落在节点安全点上，
> 不建议和「自动拉线与战报收集」一起用。

## 6. 失败分支

| 现象 | 判定 | 处理 |
| --- | --- | --- |
| `[战报收集 #n] 失败：run-round ...` | 子进程没有输出 JSON / 设备掉线 / 脚本异常 | 看 `screenshots/flow/report_collect_*.jsonl` 的错误；回地图脚本仍会执行 |
| `failedStep=capture, reason=incomplete-list` | 战报列表没翻到底 | 本轮不上传，下次收集会重试；必要时调大 `--report-max-seconds` |
| `ok=false` 且 `backToMap=false` | 收集后没回到世界地图 | 自动拉线可能停在战报页，需要人工点左上返回；下一轮 `ensure_map()` 通常能自动恢复 |
| `超过提交间隔才收集` | 长时间没有安全点 / 上传持续失败 | 检查是否用了 `--no-wait` / `--no-battle`，或把 `--report-interval` 调小到 240s；上传失败看 `pendingUploads` 与补交日志 |
| `上传 失败` | 报表服务器不可达 / 密钥不匹配 | 战报数据仍在 `skills/战报自动收录/captures/`，可用 `upload.py --capture-id` 断点补传 |

## 7. 与单独运行的关系

- 单独跑 `python skills/战报自动收录/scripts/round.py` 时，**不能**同时跑
  `flow_loop` / `flow_line_report`（同一台模拟器只能有一个触控自动化）。
- `flow_line_report` 已经把两者串行化：收集子进程与拉线主流程互斥执行，
  收集前后都会确认/恢复世界地图。
