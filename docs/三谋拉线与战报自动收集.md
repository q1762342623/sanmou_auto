# 三谋拉线与战报自动收集（热点驱动）

> 交付形态：[`skills/三谋拉线与战报自动收集/SKILL.md`](../../skills/三谋拉线与战报自动收集/SKILL.md)
> 唯一入口：`python -m sanmou_auto.atomic_loop`（旧闭环 `flow_hotspot_loop` 已删除）

## 1. 为什么改

旧流程靠同盟邮件解析战场，问题：

- 邮件可能没有坐标 / 关键字不明确 / 已经过期；
- 真正高频交战点与邮件指令经常不一致；
- 「攻占」会触发自动铺路，部队到不了目标格；
- 每次出征都重新定位据点，途中战报收集只能插空闲点。

新流程用**战报里的最高频次交战坐标**作为唯一战场来源，并按用户口径
（2026-11-23）重排顺序。

## 2. 启动阶段

1. **收集我方据点**：同盟 → 设施 → 同盟建筑（同盟大营/堡垒）+ 同盟 → 城池
   （城/水寨/军港/民港）→ `screenshots/flow/camp_cache.json`；
2. **我的主城**：右上「定位」→「建筑」第一条，点第一行并用底栏坐标校验 →
   `screenshots/flow/home_city.json`；
3. **补兵城** = 城池类据点里离主城最近的一个；
4. **首轮完整战报收集**（采集 → 提取 → 上传）→ `coordinateHotspot.hottest`
   → `screenshots/flow/latest_hotspot.json`。

实测（2026-11-23）：

```text
据点 41 个（同盟建筑 4 + 城池 37）
我的主城：神卷路明非 (648,915)
补兵城：城(641,923)，距主城 10.6 格
首轮热点：(712,786) 81 场 29.3%
最近可调动据点：城(713,806)，距热点 20.0 格
```

## 3. 每轮顺序

```text
补兵优先（已满先回城）
  → 完整战报收集（更新热点）
  → 最近据点调动（满兵参战；低兵力标记补兵送离主城最近城池）
  → 等全部调动到达（期间持续完整收集）
  → 一次性向热点：攻城 > 行军（绝不攻占；灰色则相邻格）
  → 驻留 5 分钟（持续收集；未被打回换新热点再行军，最多 3 次）
  → 右侧头像逐支「回城」撤回主城
```

用户口径逐条对应：

| 口径 | 实现 |
| --- | --- |
| 启动先收集据点 | `HotspotLineLoop.prepare_camps()` |
| 再收集主城 / 最近城池用于补兵 | `prepare_home()` + `pick_replenish_city()` |
| 战报收集取代邮件分析 | `collect_once()` + `HotspotTracker` |
| 找最近据点触发调动 | `nearest_camp()` + `Mobilizer` |
| 补兵流程 | 低兵力 → `CityReplenish`（离主城最近城池） |
| 攻城 > 行军，不要攻占 | `march.MARCH_BUTTON_PRIORITY` / `MARCH_BUTTON_EXCLUDE` |
| 行军灰色找临近可行军点 | `march.NEAR_OFFSETS` |
| 不反复定位 | 一次 `SandboxJump.goto(hotspot)`，同面板派完 |
| 全部打回后撤回主城 | `TroopReturn.return_all()`（头像 → 回城 → 不再提示 → 确定） |
| 每轮收集后判断 ready | `TroopReturn.ready_troops()` |
| 补兵部队已满优先回城 | `mobilize_phase()` 的 `replenish_returned` |
| 不因途中热点变化重新调动 | 热点只在「下一轮」或「驻留 5 分钟结束」时使用 |
| 行军不重新判断兵力 | 直接 `dispatch_one()`，不调用 `ensure_strength()` |
| 点击先 OCR 再点中心 | `Marcher.pick_action()` / `TroopReturn.return_button()` |

## 4. 实机校准记录

| 项目 | 结果 |
| --- | --- |
| 右侧头像 1-4 | `(840,295/430/545/660)`，逐支点击有效 |
| 中央「回城」 | 位置随镜头变化（y≈748 或 y≈940）；OCR 后点文字上方 35px |
| 连续回城 4 支 | `returned:[1,2,3,4]` |
| 回城确认框 | 实测「今日登录不再提示」勾选点 (435,862)、确定 (640,926)；第二次不再弹框 |
| 无效攻城回退 | 攻城面板「被攻击的建筑没有连接地」→ 换相邻格「行军」成功 |
| 多队连续派兵 | 2 队在同一相邻格连续派出（27s 到达） |
| 启动 dry-run | 据点 41 / 主城 648,915 / 补兵城 641,923 / 热点 619,749 |
| 单轮耗时 | 战报收集 4~11 分钟/次；4 队调动到达 14 分钟；整体 25~31 分钟 |


模块：

```text
sanmou_auto/hotspot.py            热点读取/跟踪/历史
sanmou_auto/troop_return.py       右侧头像 ready/回城/确认框
sanmou_auto/march.py              热点行军/攻城/相邻格

```

## 6. 已知待观察

- 「驻留 5 分钟」基于右侧头像状态判断「被打回」：如果战斗中头像既不显示
  倒计时也不显示「队列」，可能提前进入收尾；日志会打印每支状态便于复盘；
- 战报收集单次可能 5~11 分钟（列表页数多时更久），这是「每次完整收集」
  口径的预期成本；长跑时一轮 25~35 分钟属正常；
- 战报收集后偶发回不到世界地图（`backToMap=false`），收尾的头像回城
  通常仍能完成；下次 `ensure_map` 会自动恢复；
- 横屏右侧头像坐标是估算，换横屏必须重新校准。
