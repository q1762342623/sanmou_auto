## 2. 本轮改进（低画质截图管线）

### 2.1 `tools/snap.py`

- `adb exec-out screencap -p` 抓原图
- 默认缩放至宽 1000px、JPEG q68，单张约 60–140KB（约为原 PNG 的 1/20）
- 支持 `--crop x1 y1 x2 y2`、`--scale N` 做局部放大分析
- 调用示例：

```bash
python tools\snap.py screenshots\probe\_now.jpg 1000 68
python tools\snap.py screenshots\probe\_crop.jpg 600 75 --crop 1200 40 1600 200 --scale 2
```

### 2.2 `tools/probe_all.py`（v3）

- 截图统一走 `save_low()`，输出 `<id>_<name>.jpg`
- 基线只比较**静态 UI 区域**（顶栏、底栏、右队列、左图标列），忽略地图相机移动
- 关闭面板使用显式关闭按钮序列，**不再按 BACK**
- 开关类控件（D1/D2 缩放、C1 视野）点击后自动还原
- 恢复失败立即中止并保存 `_stuck_low.jpg`，避免在错误状态上继续点击

用法：

```bash
python tools\probe_all.py --base          # 记录当前干净地图为 UI 基准
python tools\probe_all.py 34 40           # 探测 REGIONS 索引 [34,40)
python tools\probe_all.py --reset         # 关闭叠加面板回到基准
```

**禁止**用 Android BACK 关闭面板：在武将页、聊天页实测会弹出「确认退出」，继续按无效。

聊天/好友面板无法通过已知按钮关闭。本轮采用：

```bash
adb shell am force-stop com.bilibili.nslg
adb shell monkey -p com.bilibili.nslg -c android.intent.category.LAUNCHER 1
```

等待约 30–40 秒重新进入地图。数据在服务端，重启不会丢失。

## 5. 对自动化程序的建议

1. **截图分级**
   - 状态判断/UI 差分：宽 240–400px 灰度缩略图
   - LLM 页面理解：宽 1000px JPEG q68
   - OCR/模板匹配：原始 1600x900 局部裁剪，不整图入库
2. **控制请求体积**
   - 单轮对话最多附 8–10 张低画质图
   - 大图只落盘，不读入模型上下文
   - 保持历史记录精简，避免再出现 52MB 请求
3. **面板恢复**
   - 优先使用页面自身返回/X，不依赖 BACK
   - 每次点击前做一次「干净地图」校验（静态 UI 区域差分）
   - 对聊天/好友面板建立白名单：自动化流程禁止点击 B6/D4
4. **坐标策略**
   - 固定 UI（A–F 区）可用绝对坐标
   - 地图标签（G 区）必须用模板匹配 / OCR 动态定位，不能写死坐标
5. **高风险按钮**
   - A9 兑换、A8 充值、D6 回城、F4 征战、E 区定位均会产生状态变化，自动化执行前需要显式确认或干跑模式
