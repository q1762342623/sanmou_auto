# 同盟管理 · 排行榜导出（抓包 → 校验 → HTML）

一句话：**点排行、逐个榜单切一遍并抓包；解出每榜完整人数，校验通过后出一页静态报表。**

```
adb 截图/触控 ─┐
                ├─→ 功能网格 → 排行（个人 / 阵营两个页签）
设备内 tcpdump ─┘        │
        │                └─ 切换榜单（首占榜切 9 级、阵营内排行切阵营）
        ↓
   rank_<批次>_<序号>_<榜单>.pcap
        ↓  scripts/pcap_codec.py（2 字节长度帧 + XOR 随机 key + sproto）
   scan_rows()：每页 50 行 → 繁荣/武勋 300、首占 100、阵营内 ~550
        ↓  scripts/collect.py（人数硬校验，不达标只重抓该榜）
   screenshots/flow/rank_probe/rank_report_<批次>.html + rank_report_latest.html
```

数据**全部来自网络包**；截图/OCR 只用于导航（网格是否展开、下拉选项定位）。

## 0. 命令一览（都在 skill 根目录执行）

| 命令 | 作用 |
| --- | --- |
| `python scripts/collect.py` | **推荐入口**：逐个榜单抓包 → 校验人数 → 不达标重抓该榜 → 生成 HTML |
| `python scripts/collect.py --tries 4` | 单榜最多抓 4 次（默认 3） |
| `python scripts/collect.py --skip-html` | 只采集、不生成页面 |
| `python scripts/probe.py --only 个人繁荣榜` | 只抓一个榜（`--only a,b` 抓多个） |
| `python scripts/probe.py --firstocc9` | 首占榜先切到 9 级再抓 |
| `python scripts/probe.py --extra` | 额外抓「阵营内排行」（讨逆军 / 太平道 各一段） |
| `python scripts/report.py` | 用最新批次重新生成 HTML |
| `python scripts/report.py --batch 20261126_011931` | 指定批次生成 |

产物目录：`screenshots/flow/rank_probe/`（pcap + 每榜截图 + HTML）。

## 1. 前置检查（每次开工做一次）

1. MuMu 已启动、游戏已登录、停在世界地图（不要在战斗/弹窗里跑）。
2. `adb devices` 能看到 `127.0.0.1:16416`；`adb root` 能成功（没有 root 就无法设备内抓包）。
3. 模拟器内存在 `/system/bin/tcpdump`。
4. 同仓存在 `skills/战报自动收录/scripts/engine/`（本 skill 复用它的拆包与 sproto 解析）。

## 2. 数据口径（**人数是硬约束，别用宽松阈值**）

| 榜单 | 完整人数 | 说明 |
| --- | --- | --- |
| 个人繁荣榜 | **300** | 每页 50 行 × 6 页 |
| 个人武勋榜 | **300** | 同上；赛季初期**少于 50 人**视为正常，不重抓 |
| 个人首占榜（9 级） | **100** | 每页 50 行 × 2 页；只看单个等级 |
| 阵营内排行 | 每阵营 ≥100（实测 549~550） | 两个阵营的同盟集合**不能有交集**（有交集=串阵营，重抓） |

- 行数据走 `scan_rows()`（**sproto 数组解析**，每页固定 50 项）。
  **不要**用按行标记切分的旧口径：个别行的分数/名次字段被省略（编码变体），
  会把 300 人切成 293~295、100 人切成 97。
- 同一页可能被抓到多次，按帧内容 md5 去重后计数，不会重复累加。
- 首占榜的数值列是**占领时间戳**（如 `1794028742`），不是分数。

## 3. 抓包关键细节（踩过的坑）

- **抓包窗口只放一次榜单切换**：解码器会把整条 TCP 流合并成一个 chunk，
  同一段包里的多个榜单无法再按时间窗口区分，所以「一个榜单一段 pcap」。
- **点已经选中的默认榜不会发请求**：要先点同页签的兄弟榜再点回来（`SIBLING`）。
- **首占榜**：把「点开榜单（默认 12 级）」放到窗口**外**，窗口内只切 9 级，
  否则 12 级 + 9 级两批混在一段包里（会变成 ~200 行）。
- **阵营内排行**：「先切到另一个阵营预热」也要放到窗口**外**（同样为了不串数据），
  窗口内只做「切回目标阵营」。
- 首占榜等级下拉 / 阵营下拉同一个位置 `(728,1279)`：等级列表要先上滑一小段才能点到 9 级；
  阵营两项必须用 **OCR 定位**（目测坐标会点到空处）。

## 4. HTML 报表内容

| 区块 | 内容 |
| --- | --- |
| 顶部 | 每榜「N 帧 × 每帧 50 行 → 300 行（目标 300 行 · 完整）」 |
| 个人繁荣榜 / 个人武勋榜 | 按同盟汇聚：上榜人数 / 合计 / 平均 / 最高 / 最低，按合计降序 |
| 个人首占榜（9 级） | **只做分类**：同盟 / 上榜人数 / 占比（按人数降序）；上方标「最后一位（第 100 名）占领时间」 |
| 阵营（讨逆军 / 太平道各一张表） | 两个输入框：**问鼎人数 X**、**紧接的霸业人数 Y**（都是人数，不是截止名次）；逐盟给出 问鼎人数 / 问鼎占比（÷X）/ 霸业人数 / 霸业占比（÷Y）/ 问鼎+霸业 / 合计占比（÷(X+Y)）。没有「未获得」列，输入存 localStorage |

阵营名额按**名次区间**分配：前 X 名问鼎，第 X+1 ~ X+Y 名霸业，其余未获得；
X/Y 超界自动裁剪（X ≤ 总人数、Y ≤ 总人数−X）。

## 5. 常见问题

| 现象 | 处理 |
| --- | --- |
| 繁荣/武勋只有 293~295 行 | 用了旧的行标记口径；确认走 `scan_rows()` |
| 首占榜只有 97 行 | 同上；另外确认窗口内只有 9 级 |
| 某个榜 0 行 | 服务端没重发：换兄弟榜再点回来，或 `--cold` 冷启动再抓一次 |
| 两个阵营同盟重合 | 「预热切阵营」漏放到窗口外了 |
| 解码全是乱码 | XOR key 每次连接随机：`discover_key()` 需要整批帧一起打分，别按单段包解 |
| 下拉点不中 | 用 OCR 找文本再点（`select_dropdown_item()`），别写死坐标 |

技术细节（协议结构、全部坐标、逐榜单帧数、发现过程）见
[`reference/rank-leaderboards.md`](reference/rank-leaderboards.md)。
